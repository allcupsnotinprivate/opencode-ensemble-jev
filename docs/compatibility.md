# Протокол совместимости — 2026-11-23

**Проверено локально:** macOS arm64, Git, OpenCode CLI/Plugin 2.3.2, `@hueyexe/opencode-ensemble@0.21.5`, Bun 1.4.5. В CI описан Linux runner; локальный запуск не является результатом GitHub Actions.

| Эксперимент | Наблюдаемое свидетельство |
|---|---|
| Phase 0 `--probe` | Минимальный V2-плагин заменил `event.input.model` внутри `execute.before` вложенного `tools.team_spawn`. Mock **генеративный** сервер получил `model: "probed"` от реальной дочерней сессии. |
| Оба плагина, ключ отсутствует | Два spawn без model; endpoint получил `strong` для миграции и `fast` для документации. В JSONL `missing-key`. |
| `--decisions` | С теми же задачами подменён только транспорт Jev. Endpoint получил **balanced и strong**, отличный от fallback результат. `accepted-tier`, confidence и стоимость записаны в JSONL. |
| Изоляция и merge | Два checkout в `git worktree list`. Первый агент через реальный `shell` записал файл и закоммитил в своей ветке. До merge у Lead файла нет. `team_status`, `team_results`, `team_shutdown`, `team_merge`; проверено содержимое в основном checkout после merge. |
| Agent lifecycle | Два ошибочных `team_claim` несуществующей задачи приводят к тактической записи. `team_message` о завершении критичного изменения приводит к отдельному `deep` review и записи инструкции Lead. |
| `--broken` | Тестовая стратегия worktree бросает ошибку. Ensemble продолжает spawn, но запрос пишущего агента получает текст об отказе и **ни одного инструмента**. |
| `--invalid` | При невалидном JSON `jev_status` сообщает `invalid-config`, а вложенный `team_spawn` возвращает отказ; нового worktree нет. |
| Несколько задач | Один дочерний агент завершает две разные задачи на доске. `team_tasks_complete` выдаёт отдельные review по описаниям документации и миграции; отчёт по исходному назначению обрабатывается отдельно. |

В тестах используются локальные генеративные модели: они выдают сценарий вызовов, но не выполняют инструменты и не управляют Git. Вызовы, дочерние сессии, permissions, смена каталога и merge выполняются настоящими OpenCode и Ensemble.

После повторного ревью проверены адресные инструкции в запросе Lead, восстановление очереди без нового шага исполнителя, независимая отмена подписчиков кеша и отказ до вызова Decisions при пустом каталоге. Усиленная валидация распределений также прошла отдельный smoke с реальным OpenRouter. Команды для проверки текущего состояния приведены в README.

**Важная деталь:** созданный worktree сам по себе не доказывает изоляцию сессии. На проверенной связке встречался старт в директории родителя. При совпадении директорий берём назначенный Ensemble абсолютный путь из session permissions, проверяем `realpath` и инвентарь обычного Git и ставим `ctx.session.move` перед первой задачей. Перед dispatch дополнительно проверяются location плагина и сессии. Если Worktree не создан, применяется deny на инструменты. Это интеграционный контракт с указанной версией Ensemble; после обновления повторите все пять запусков.

## Известные границы

- Отдельный `tests/live/openrouter.ts` прошёл с реальным ключом: OpenRouter Decisions API принял пакет вопросов `choice`, `score` и `noul` к `typesafe/jev-1.13`. Для синтетической задачи по документации получен `fast`, confidence `0.98`, `usage.cost` — $0.00002415. Сквозной тест Ensemble использует тестовый transport; один живой запрос не измеряет общую точность маршрутизации.
- Основной режим — выбор при spawn. `experimental.model.resolve` действует на запрос в рамках одного провайдера; не реализованы автоматические переключения в активной сессии. Любой явный model в аргументах считается выбором пользователя: его происхождение hook не различает.
- Маршрутизатор действует в location, где оба плагина активны в указанном порядке. Регистрируйте их глобально либо в закоммиченной конфигурации. Это не песочница Git и не защита от произвольного кода пользователя.
- Бюджет и подавление повторов действуют в памяти экземпляра, не во всех рабочих деревьях или процессах вместе. История JSONL сохраняется, но `jev_status` и `jev_decisions` не восстанавливают статистику после перезагрузки. Файл журнала нужно ротировать отдельно.
- Эвристики чувствительных изменений и родов работы ориентированы на русский и английский. Завершение без явного сообщения или операции на доске не считается подтверждённым результатом. При больших пачках задач начальная оценка ограничена `maxAgents`.
- Не проверены Windows, последующие версии OpenCode, Git URL уже опубликованного пакета и долгие реальные stalled-сессии. Нет автопубликации.
